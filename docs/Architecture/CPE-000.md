# 1. Executive Summary

The Claire Performance Engine (CPE) provides the communication intelligence layer of the Claire Project.

Its responsibility is to transform a Performance Context into an immutable, backend-independent PerformanceGraph.

The PerformanceGraph serves as the authoritative contract between CPE and CAM (Claire Acoustic Model).

Compatible acoustic implementations may also consume the PerformanceGraph when they satisfy the CAM contract.

CPE performs no acoustic synthesis.

CPE performs no backend-specific reasoning.

Its sole responsibility is communication reasoning and performance planning.

-------------------------------------------------------------------------------

# 2. Background

The Claire Project separates speech generation into three independent layers:

- Claire Speech Engine (CSE) — framework, lifecycle, and runtime infrastructure
- Claire Performance Engine (CPE) — communication intelligence and performance planning
- Claire Acoustic Model (CAM) — native acoustic rendering and speech generation

CPE occupies the middle layer.

It receives contextual information from CSE and produces a PerformanceGraph consumed by CAM.

(Compatible acoustic implementations may separately consume the PerformanceGraph if they satisfy the CAM contract.)

-------------------------------------------------------------------------------

# 3. Objectives

The architecture SHALL:

- Separate communication reasoning from acoustic synthesis.
- Produce an immutable, backend-independent PerformanceGraph.
- Produce deterministic results for identical inputs.
- Establish the authoritative contract for CAM.
- Allow compatible acoustic implementations to consume the PerformanceGraph contract via translation.
- Remain modular, extensible, and free of neural/learned synthesis dependencies.

-------------------------------------------------------------------------------

# 4. Scope

## In Scope

- Performance reasoning (Meaning, Intent, Planning)
- Internal architecture and module boundaries
- Reasoning pipeline definition
- PerformanceGraph construction and validation
- Stable contract with CAM (and compatible translators)

## Out of Scope

- Acoustic waveform generation
- Vocoders and neural speech synthesis
- Acoustic model training or neural network design
- Backend implementation details

-------------------------------------------------------------------------------

# 5. High-Level Architecture

```text
Performance Context
        │
        ▼
Claire Performance Engine (CPE)
[ Meaning Pass → Intent Pass → Planning Pass ]
        │
        ▼
PerformanceGraph Builder
        │
        ▼
PerformanceGraph (Contract)
        │
        ▼
Claire Acoustic Model (CAM)
        │
        ▼
Speech / Audio
```

CPE remains completely unaware of acoustic renderer implementation details. Compatible acoustic implementations (such as KittenTTS) may consume the PerformanceGraph via translation when satisfying the CAM contract.

-------------------------------------------------------------------------------

# 6. Core Components

The Claire Performance Engine consists of the following logical components:

### Performance Context

Provides the complete input required for performance reasoning.

Fields:
- `text`: Spoken textual input (Required)
- `character_state`: Speaker emotional / character context (Optional)

---

### Reasoning Pipeline

Responsible for sequential, deterministic communication reasoning:
1. **Meaning Pass**: Extracts semantic content from the context.
2. **Intent Pass**: Determines communicative intent and goals.
3. **Planning Pass**: Generates the expressive delivery plan (pitch, pace, emphasis).

---

### PerformanceGraph Builder

Constructs the canonical, immutable, backend-independent `PerformanceGraph` encapsulating text, character state, semantics, intent, and delivery plan.

---

### Validation Layer

Verifies that the generated `PerformanceGraph` satisfies structural integrity, immutability, and schema rules.

-------------------------------------------------------------------------------

The `PerformanceGraph` is passed to CAM for native synthesis. Compatible acoustic implementations may translate the graph to satisfy the CAM contract.

-------------------------------------------------------------------------------

# 8. Architectural Principles

The Claire Performance Engine SHALL:

- Remain independent of every acoustic model.
- Never generate audio.
- Never contain renderer-specific logic.
- Preserve deterministic behavior.
- Preserve the original input text.
- Produce an immutable `PerformanceGraph`.
- Form the unambiguous contract between CPE and CAM.

-------------------------------------------------------------------------------

# 9. Interfaces

## Input Interface

`PerformanceContext`

Fields:
- `text` (Required)
- `character_state` (Optional)

---

## Output Interface

`PerformanceGraph`

The immutable data structure defining communicative intent, semantic payload, and delivery plan consumed natively by CAM (or adapted via `BaseTranslator` for compatible implementations).

-------------------------------------------------------------------------------

# 10. Error Handling

The architecture SHALL:

- Detect invalid PerformanceContext objects.
- Reject malformed performance graphs.
- Preserve deterministic failures.
- Avoid backend-specific exceptions within CPE.

-------------------------------------------------------------------------------

# 11. Extension Philosophy

Future extensions (such as PRD-026 deterministic intent enrichment) SHALL:

- Add modular passes or refine deterministic reasoning without altering the pipeline architecture.
- Preserve backward compatibility with existing PerformanceGraph consumers.
- Maintain Constitution compliance.
- Preserve backend independence.
